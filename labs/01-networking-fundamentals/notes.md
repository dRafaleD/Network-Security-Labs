# Day 1 — Networking Fundamentals and Packet Observation

[🇬🇧 English](notes.md) | [🇹🇷 Türkçe](notes.tr.md)

## Goal

Understand the basic pieces involved when your computer communicates over a network and observe real traffic generated by your own machine.

## Core concepts

- **IP address:** identifies a host/interface on an IP network.
- **MAC address:** link-layer address used for communication on the local network.
- **Default gateway:** the router your host normally sends traffic to when the destination is outside the local network.
- **Packet:** a unit of data transmitted across a network.

A useful simplified model is:

```text
Application
    ↓
TCP / UDP
    ↓
IP
    ↓
Ethernet / Wi-Fi
```

## Lab 1 — Inspect your interfaces

On Linux:

```bash
ip addr
```

Look for:

- interface names
- IPv4/IPv6 addresses
- MAC addresses
- loopback interface (`lo`)

Then inspect routes:

```bash
ip route
```

Find the line beginning with `default via`. The address after it is normally your default gateway.

## Lab 2 — Generate simple traffic

Test connectivity to a public resolver:

```bash
ping -c 4 1.1.1.1
```

Then try a hostname:

```bash
ping -c 4 example.com
```

The second command also requires name resolution before packets can be sent to the destination IP.

## Lab 3 — Observe your own packets

List interfaces:

```bash
sudo tcpdump -D
```

Capture ICMP traffic on the appropriate interface:

```bash
sudo tcpdump -n -i <interface> icmp
```

In another terminal:

```bash
ping -c 4 1.1.1.1
```

Observe request/reply pairs.

The `-n` option keeps addresses numeric, which makes the first exercise easier to follow.

## Wireshark alternative

Start a capture on your active interface and use the display filter:

```text
icmp
```

Run the ping again and inspect:

- Source
- Destination
- Protocol
- Echo request
- Echo reply

## Questions

1. What is your active network interface?
2. What is its private IP address?
3. What is your default gateway?
4. What source and destination IP addresses appear in the ICMP request?
5. What changes when you ping a hostname instead of an IP address?

## Main takeaway

Do not treat networking as invisible magic. A command such as `ping` produces observable traffic with identifiable source, destination, protocol, and direction.

For network security, learning to read that traffic is more important than memorizing tool commands.
